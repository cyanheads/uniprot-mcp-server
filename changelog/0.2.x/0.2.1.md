# 0.2.1 — 2026-06-28

## Changed

- **`uniprot://entry/{accession}` outlines oversized records** — an annotation-heavy entry over the outline budget now returns a bounded identity summary plus a section outline (`sections[]` with names and serialized byte sizes) instead of injecting the whole record (P04637 serializes to ~360 KB). Re-call guidance routes to the `uniprot_get_entry` tool's `sections:[...]` path, since the resource URI takes no sections argument. ([#6](https://github.com/cyanheads/uniprot-mcp-server/issues/6))

## Fixed

- **`uniprot_get_proteome` truncation `notice`** — the paging guidance written by `ctx.enrich.truncated()` was not declared in the enrichment block, so the effective-output parse stripped it from both `structuredContent` and the `content[]` trailer; text-only clients saw the cap but not how to reach the rest. The `notice` field is now declared and the guidance survives into `content[]`. ([#4](https://github.com/cyanheads/uniprot-mcp-server/issues/4))
- **`uniprot_get_proteome` / `uniprot_get_taxonomy` conflicting identifiers** — supplying both identifiers (`upid` + `taxon_id` for proteome, `taxon_id` + `name` for taxonomy) silently resolved down one path and could answer the wrong organism. Both tools now reject the contradiction with a typed `conflicting_identifier` error (`InvalidParams`). An empty-string or whitespace identifier alongside a real one is still treated as the single-identifier path, not a conflict. ([#5](https://github.com/cyanheads/uniprot-mcp-server/issues/5))
