# 0.2.6 — 2026-10-12

## Added

- **`uniprot_get_entry` `section_limit` (1–500) and `section_offset`** window one list section, such as p53's natural variants; the result reports `window`, `totalCount`, and `nextOffset`, and a bad window fails `invalid_section_window` (#9).
- **`uniprot_get_entry` `absentSections`** lists each requested section the record lacks (#7).
- **`uniprot_get_taxonomy` `cursor` pages `include_children`**, 100 per page, with `totalChildren` and a truncation notice. The emitted cursor is bound to its taxon (`<taxonId>.<cursor>`), and one sent with another taxon fails `invalid_cursor` (#12).
- **`uniprot_search_proteins` `inactive[]`** and a **`uniprot_map_ids` `inactive` marker** (reason, replacement accessions, UniParc ID) report merged, demerged, and deleted accessions (#21).
- **`uniprot_get_sequence` `mergedFrom`** names the requested accession when a merged one returns its merge target's sequences (#11).
- **`bun run test:coverage`** runs the suite with Istanbul coverage against the framework thresholds (#19).

## Changed

- **`uniprot_search_proteins` `reviewed: false` now searches Swiss-Prot and TrEMBL together.** It used to restrict to TrEMBL, so a call that still succeeds returns a different result set; put `reviewed:false` in `query` for TrEMBL only (#10).
- **`uniprot_get_entry`, `uniprot_get_sequence`, and the `uniprot://entry/{accession}` resource report an inactive accession** (merged, demerged, or deleted) in `failed[]` or as `not_found`, with the reason and the successor or UniParc ID, where they used to return a hollow record (#11).
- **`uniprot_get_entry` with `sections` on a multi-accession call fails `sections_single_accession`** where `sections` was silently ignored. Section keys match case-insensitively (#7).
- **Unbounded lists in `uniprot_get_entry` `content[]` are capped** with a runnable "N more not shown" line; xref ids past 30 per database are disclosed and stay in `structuredContent` (#9).
- **`uniprot_map_ids` no longer offers `UniProtKB_AC-ID` as a `to_db` target**, which UniProt rejected for every source; it stays valid as `from_db` (#24).
- **UniProt 400 rejections keep their context**: `invalid_query` on `uniprot_search_proteins` and `uniprot_get_proteome`, `invalid_fields` on `uniprot_get_entry`, each relaying UniProt's bounded `messages[]`. A bad or stale `cursor` on search, proteome, or taxonomy children fails `invalid_cursor`, where UniProt's HTTP 500 surfaced as a generic upstream failure; 502, 503, 429, and timeouts stay upstream errors (#8).
- **Id-pattern rejections on five inputs say what a valid id looks like** (#17).
- **`uniprot_get_taxonomy` and the taxonomy resource map a taxon ID UniProt can't parse to `not_found`** (#12).
- **`uniprot_protein_dossier` `prompts/get` without `arguments` fails naming the missing `identifier` field**, and resource `params` rejections carry the bounded `data.issues` (cyanheads/mcp-ts-core 0.13.15).

## Fixed

- **`uniprot_search_proteins` wraps the caller's `query` or `text_search` as `(<clause>) AND …`** whenever the tool appends a filter, so a top-level `OR` stays filtered on every branch. Unbalanced parentheses fail `invalid_query` before any request, with 1-based character positions, and a trailing unescaped `\` is padded so it cannot escape the tool's own `)`. `uniprot_get_proteome` `include_proteins` queries get the same grouping and guard (#10).
- **`uniprot_get_taxonomy` name queries escape a double quote** (#22).
- **`uniprot_map_ids` checks a `ticket` or continuation job ID for shape before any request**, failing `invalid_ticket` or `invalid_continuation`.
- **An empty relayed upstream message is dropped** from error text.
