# 0.2.4 — 2026-09-20

## Changed

- **Session mode resolves to `stateless` on every launch path** ([#16](https://github.com/cyanheads/uniprot-mcp-server/issues/16)). `createApp({ sessionMode: 'stateless' })` declares it in source and `.env.example` sets it actively, where only the container image did before; an HTTP deployment that wants session affinity must now set `MCP_SESSION_MODE=stateful`.
- **An out-of-schema argument is rejected as `InvalidParams` (`-32602`)**, not `ValidationError` (`-32007`), and carries `data.reason: "invalid_arguments"` plus a schema-derived `data.recovery.hint` naming the offending field.
- **Tool error text closes with a `(reason <reason>)` term** so a text-only client can branch on the same identifier `structuredContent.error.data.reason` carries. A test pinning that text byte-exact will move.
- **The upstream request URL never reaches client-facing `error.data`** — a UniProt request URL echoes the caller's query, so the service's leak guard treats `url` as an upstream internal alongside `responseBody` and `statusCode`.
- **`engines.bun` raised to `>=1.4.0`**, matching the framework floor.
- **Framework skills moved from `skills/` to `framework-skills/`**, so a plugin install no longer hands this server's development skills to the installing agent.
