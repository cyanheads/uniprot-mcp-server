# 0.2.2 — 2026-08-21

Everything below the first bullet arrives with `@cyanheads/mcp-ts-core` `^0.12.3`.

## Changed

- **Eight typed contract errors move from `InvalidParams` (-32602) to `ValidationError` (-32007)** — `uniprot_search_proteins` (`missing_query`, `conflicting_query`), `uniprot_map_ids` (`missing_inputs`, `unsupported_db_pair`), and `uniprot_get_proteome` / `uniprot_get_taxonomy` (`missing_identifier`, `conflicting_identifier`). `data.reason` and the recovery hints are unchanged; `-32602` now belongs to the framework's own schema-edge rejection.
- **Tool inputs are strict** — an argument key a tool does not declare is rejected by name before the handler runs, and every advertised `inputSchema` carries `additionalProperties: false`. Root level only; a nested object still strips.
- **The advertised `outputSchema` declares the error envelope** — success fields become optional and `error` is declared, so a client that validates `structuredContent` without checking `isError` stops rejecting error results with `-32602`.
- **Advertised JSON Schema is 2020-12**, not draft-07, and the HTTP endpoint serves protocol revision `2026-07-28` alongside the 2025 revisions.
- **`ctx.log` reaches the client** as `notifications/message`, gated by the client's `logging/setLevel`.
- **`uniprot_get_entry`'s `content[]` header** reads `**Result kind:** <kind>` instead of `_Result: <kind>_`.
- **Security reports go to `security@caseyjhand.com`.**

## Fixed

- **A throttled `rest.uniprot.org` response honors `Retry-After`** — the retry wrapper waits the requested delay (delta-seconds or HTTP-date) instead of its own backoff schedule.
- **Tool input-validation failures read as flat `path: message` sentences**, not a serialized `ZodIssue[]` blob.
