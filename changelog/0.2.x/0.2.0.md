# 0.2.0 — 2026-06-27

Breaking relative to 0.1.1: `uniprot_get_entry` no longer wraps its output in a `result` key — read `structuredContent.succeeded[]` / `failed[]` / `sections[]` directly.

## Changed

- **`uniprot_get_entry` output flattened (breaking)** — the `result` wrapper and the discriminated union are removed; the output schema is now a flat object with a top-level `kind` (`"full" | "outline"`) and optional `succeeded[]`, `failed[]`, and `sections[]`. Access paths change from `structuredContent.result.succeeded[]` to `structuredContent.succeeded[]`, matching the tool description and every other tool in the server. Outline re-call guidance now surfaces through `enrichment.notice` rather than an output field. ([#2](https://github.com/cyanheads/uniprot-mcp-server/issues/2))

## Fixed

- **`uniprot_get_sequence` isoforms** — `include_isoforms: true` always returned empty because the per-accession FASTA endpoint silently ignores `includeIsoform`. The isoform path now goes through the search endpoint (`/uniprotkb/search?query=accession:{accession}&format=fasta&includeIsoform=true`), which returns the canonical plus every isoform; the canonical-only path stays on the cheaper per-accession endpoint. ([#1](https://github.com/cyanheads/uniprot-mcp-server/issues/1))
- **`uniprot_search_proteins` custom `fields`** — a caller-supplied projection (e.g. `accession,gene_names`) could drop columns the required `ProteinHit` output schema demands, crashing response validation on the missing `entryName`. The new `MANDATORY_SEARCH_FIELDS` identity/provenance set is now merged into every search request, mirroring the existing `uniprot_get_entry` field guard. ([#3](https://github.com/cyanheads/uniprot-mcp-server/issues/3))
