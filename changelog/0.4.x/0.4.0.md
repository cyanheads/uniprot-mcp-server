# 0.4.0 — 2026-11-03

## Added

- **`skill://uniprot-guide/SKILL.md`** resource: the published `skills/uniprot-guide/` skill is served over MCP (`createApp({ skills: 'skills' })`) and ships in the npm package, Docker image, and `.mcpb` bundle.
- **`uniprot_map_ids` `totalMappings`** (UniProt's job-wide `x-total-results`) and, for UniProtKB targets, `entryName`, `reviewed`, `organism`, and `gene` on each row; missing fields stay absent ([#38](https://github.com/cyanheads/uniprot-mcp-server/issues/38)).
- **Agent Plugins `plugin.json` and `mcp.json`** at the repository root.

## Changed

- **`uniprot_search_proteins` `organism_id`** now sends `taxonomy_id:`, so a species ID includes strains and subspecies; use `organism_id:<id>` inside `query` for an exact node. A cursor saved from 0.3.x for a search that set `organism_id` fails `invalid_cursor`, since its effective query changed; restart without it ([#31](https://github.com/cyanheads/uniprot-mcp-server/issues/31)).
- **`uniprot_map_ids` `tax_id`** stays an exact taxon node; descriptions and empty-page guidance say so and point to `uniprot_get_taxonomy` for the strain ID ([#31](https://github.com/cyanheads/uniprot-mcp-server/issues/31)).
- **`uniprot_search_proteins` `text_search`** escapes Lucene punctuation and quotes standalone `AND`/`OR`/`NOT`; only `query` accepts operators and field syntax, and unbalanced-parenthesis checks apply to `query` alone. A 0.3.x `text_search` cursor fails `invalid_cursor` the same way when its text held Lucene punctuation or a standalone `AND`/`OR`/`NOT`; plain words keep paging ([#37](https://github.com/cyanheads/uniprot-mcp-server/issues/37)).
- **`uniprot_get_taxonomy` `name`** resolves by exact match across scientific, common, mnemonic, and alias names (`human` → 9606); ties fail `ambiguous_name`, partial matches `no_exact_match`, and a scan past the 45-second budget `incomplete_candidates`, each with candidate taxon IDs ([#33](https://github.com/cyanheads/uniprot-mcp-server/issues/33)).
- **`uniprot_get_proteome` `taxon_id`** falls back to a unique descendant reference proteome; several candidates fail `ambiguous_proteome` with UPIDs and taxon IDs. A protein `query` is echoed, and an empty result says nothing matched ([#32](https://github.com/cyanheads/uniprot-mcp-server/issues/32)).
- **`uniprot_map_ids` failed jobs** fail `mapping_failed` with UniProt's `errors[].message` and recovery guidance, in submission and ticket modes; `unsupported_db_pair` is reserved for an explicitly rejected database pair at submission ([#39](https://github.com/cyanheads/uniprot-mcp-server/issues/39)).
- **`uniprot_map_ids` optional reads** (job metadata, UniProtKB identity) that fail with 400, 401, 403, 404, 422, 429, 5xx, or a timeout fall back to generic rows with a notice that identity is unavailable, so jobs above UniProt's 100,000 mapped-ID enrichment limit (a 400 on the identity read) stay pageable without identity; malformed JSON still fails ([#38](https://github.com/cyanheads/uniprot-mcp-server/issues/38)).
- **`uniprot_map_ids` `mappedCount`** counts the current page, and `unmappedIds` is job-wide, repeated on every completed page ([#38](https://github.com/cyanheads/uniprot-mcp-server/issues/38)).
- **`.mcpb` bundle** ships the skill and now also excludes `src/`, `scripts/`, `docs/`, `changelog/`, `CLAUDE.md`, `AGENTS.md`, repository config files, and plugin manifests. `scripts/clean-mcpb.ts` narrows the framework 0.13.18 agent-doc pattern to package-root agent docs, so the MCP SDK's `dist/ext/skills/` runtime that serves the skill stays in the bundle ([cyanheads/mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794)), and also strips node-gyp build output and build-only package files.
- **`uniprot_protein_dossier`** prompt checks each candidate's identity, organism, and reviewed status before selecting an accession.
